# 研究来源策略与执行设计

状态：Proposed，先作为实现契约，再逐步启用连接器

## 结论

GEA 采用“全网公开网页搜索为默认，官方 API/授权数据按需启用，证据不足时明确降级”的来源策略。用户不需要先选择小红书、抖音等平台；Agent 根据研究问题和证据缺口决定是否追加社交信号任务。

GPT Researcher（或 GPT）只负责拆解问题、扩展查询、发现和整理候选资料。GEA Harness 负责权限、预算、任务依赖、连接器可用性、停止条件、来源快照、去重、审计和报告结论边界。外部引擎返回的 URL 必须经过 GEA 连接器重新采集后才能进入报告。

## 来源决策

1. 先从 Brief 推导 `evidenceNeeds`：市场事实、第一人称表达、行为指标、官方平台数据、竞品比较和一手研究。
2. 默认创建一条公开网页研究任务，建立事实和背景基线。
3. Brief 明确提及平台，或研究方法选择“Scout Agent”时，追加社交信号任务。任务名称必须标明采集模式：官方 API，或公开网页搜索（非站内爬虫）。
4. 连接器不可用、被限流或不合规时，按顺序降级为公开网页、工作区 Context、用户上传/访谈材料；不得伪装成已获得平台级数据。
5. 行为问题没有帖子级互动字段或行为日志时，只输出方向性判断，并把缺口和所需材料写入报告。

## 证据等级

| 等级 | 来源 | 可支持的结论 |
| --- | --- | --- |
| A | 官方 API、授权数据、用户提供的原始材料 | 平台观察或一手事实，仍需记录时间范围和权限 |
| B | 公开网页正文、公开报告、公开帖子页面 | 可核查的事实、主题和方向性信号 |
| C | 搜索摘要、模型推断、合成 Persona | 线索或假设，不得写成已验证事实 |

报告必须分别标注网页事实、平台观察、AI 合成推演和模型建议。搜索引擎收录的小红书/抖音页面不等于站内搜索或站内爬虫结果。

## 任务与交互

研究计划先展示“来源策略摘要”和预计证据类型，再执行任务。执行中只展开当前任务、失败任务和需要用户操作的任务；连接器完成后折叠详情，但保留审计入口。需要用户上传授权数据、确认范围或补充平台账号时，自动滚动到对应表单。

## 连接器注册表

每个平台连接器必须声明：`provider`、能力（search/collect）、是否官方、权限范围、robots/条款限制、速率和数据保留策略。当前注册表只启用公开网页搜索和可选的 Bluesky 官方公开 API；小红书、抖音、微博、B 站和知乎默认仅走公开网页搜索，不执行登录绕过或站内爬虫。新增连接器先补注册表、合规说明、审计字段和降级测试，再接入 Agent。

## 分阶段实施

- Phase 1：策略层、任务输入中的 `evidenceNeeds`、公开网页和现有 Bluesky 审计（本次）。
- Phase 2：连接器注册表 API、能力探测、来源分层 UI、证据缺口驱动的动态 replan。
- Phase 3：受限站内爬取 Worker（仅获得授权的域名，Crawlee/Playwright 作为隔离适配器），并补充 robots、速率、数据删除和安全审计。
- Phase 4：Context Asset/向量检索与 rerank；保存知识库必须是用户明确动作或确认后的提议。

## 验收标准

- 未指定平台时，计划不显示虚构的平台任务，默认显示全网公开网页研究。
- 指定小红书或抖音时，任务明确写“公开网页搜索（非站内爬虫）”。
- 指定 Bluesky 且连接器启用时才使用官方 API，否则自动回退并记录原因。
- 行为/因果问题在证据不足时降低报告等级，不生成“平台已验证”措辞。
- 每个来源都能追溯到 connector run、候选、快照、观察和采集时间。
