# 技术要点速查

## 1. 架构分层

| 层 | 代码/组件 | 面试要点 |
|---|---|---|
| Web/UI | `src/app`、`src/components` | App Router、Server/Client Components、表单和页面状态 |
| API | `src/app/api` | Route Handler、鉴权、限流、Zod 输入校验、领域服务调用 |
| 领域服务 | `src/lib` | 研究、访谈、Agent、Context、Skill、报告和权限逻辑 |
| 持久化 | `src/lib/db.ts`、`supabase/migrations` | PostgreSQL source of truth；事务、索引、RLS/工作区隔离 |
| 异步执行 | `scripts/research-worker.mjs`、Harness | queue、lease、依赖、恢复、重试、取消、checkpoint |
| Provider | `src/lib/openai-provider.ts`、连接器 | 结构化输出、模型路由、fallback、流式/非流式适配 |
| 隔离执行 | `services/sandbox-runner` | Docker/Podman 临时容器和运行时限制 |

## 2. 研究运行状态机

```text
pending/queued -> running -> completed
                    |          |
                    |          `-> failed -> retry/new run
                    |
                    `-> waiting_input -> queued -> running
                    `-> cancelled
```

研究计划确认是启动门槛。`finish` 不能绕过必需任务、证据要求、judge 和 finalize gate。

## 3. 为什么用数据库任务 ledger

“把任务写进数据库，是为了让异步系统在进程重启后仍知道做到哪一步。内存 Promise 只能解决一次请求；数据库 ledger 能支持多个 worker、lease 过期恢复、幂等、审计、回放和 UI 刷新后的权威状态。”

任务通常包含 task key、依赖、状态、输入、输出 artifact、错误、重试信息、Skill 版本和产生它的 reasoning decision。

## 4. 幂等、lease 和 checkpoint

- 幂等：以 `runId:taskKey` 等稳定键记录 invocation，重复投递返回或更新同一条记录，避免重复写 artifact。
- Lease：worker 领取 job 时写入 `lease_owner` 和过期时间；心跳续租。进程挂掉后，其他 worker 只接管已过期 lease。
- Checkpoint：在任务 wave、上下文刷新、动态 replan 等边界记录可恢复状态；恢复时先读取已完成任务和 artifact，不重复执行已完成调用。
- 重试：按 timeout、rate limit、5xx/upstream 与 validation/configuration 分类；前几类可重试，参数、权限和 schema 错误直接终止或等待用户输入。

## 5. DAG 和动态任务

初始研究计划是固定 DAG，便于预测依赖和报告门槛。Agent 可以提出 `replan`，但不能直接插 SQL；唯一入口 Plan Mutation Service 会检查模板白名单、工具匹配、依赖、动态任务上限、Skill 版本和报告 gate。动态任务统一写入 `study_tasks`，所以仍然可以恢复和回放。

当前 rollout 以 `off/shadow/active` 灰度：`off` 只跑确定性 DAG，`shadow` 记录 Agent 决策但不改变执行，`active` 才执行通过 Harness 校验的动作。active 需要失败率、拒绝率、工具匹配率、模板匹配率和报告 gate 达标，否则自动降级。

## 6. 证据和报告

报告流水线是：研究问题/answerability -> 来源采集 -> evidence catalog/graph -> 报告草稿 -> 独立 judge -> 通过则 finalize，不通过则基于原证据定向 revise。

证据等级要说清楚：

| 来源 | 能支持什么 |
|---|---|
| 官方 API、授权数据、用户原始材料 | 一手事实或平台观察，仍需时间范围和权限 |
| 公开网页正文、公开报告、公开帖子 | 可核查事实、主题和方向性信号 |
| 搜索摘要、模型推断、合成 Persona/访谈 | 线索或假设，不能写成已验证事实 |

行为和因果问题如果没有真实行为日志或实验数据，只能给方向性结论，并列出证据缺口。

## 7. Context 检索

Context 是有用途和范围的版本化资产，不是把所有历史对话塞进 Prompt。系统可以按 user/workspace/study/system scope 检索，保存 retrieval snapshot、命中 chunk 和引用。当前设计支持词法/元数据与 embedding 的 hybrid retrieval，并可做人工相关性评估。checkpoint 工作状态不会自动升级为长期 memory；长期记忆需要明确 promotion 和来源。

## 8. Provider 和结构化输出

Provider wrapper 统一计划、澄清、研究、Persona、访谈、报告 judge、实时访谈和 Agent turn 的 schema。Zod 的作用是运行时验证模型输出，避免“模型返回一段 Markdown，服务器误当成功”。Universal Agent 如果首轮不是合法 JSON，会发送一次只允许 JSON 的修复请求；修复后仍要经过同一 schema。

Responses API 负责模型输出和事件流语义，Harness 负责执行循环、权限、恢复和审计。不能把普通一次性 Chat Completions 响应宣传成 token streaming。

## 9. SSE 进度流

SSE 适合服务器持续向浏览器推送单向事件：工具开始、进度、完成、报告生成和错误。数据库事件表是事实来源，SSE 只是传输层；客户端断线时用 `Last-Event-ID`/游标请求缺失事件。单步输出有大小上限，只发送摘要、状态、工具名和错误码，不发送隐藏 Chain-of-Thought、完整系统 Prompt 或密钥。

## 10. Skill Gateway

Skill 是版本化可执行契约，包含 manifest、输入 schema、输出协议、能力和 grant。执行前检查 workspace 是否启用、版本是否锁定、capability 是否允许、请求 hash 和预算是否匹配。MCP、HTTP 和 Sandbox 是不同 executor，但都经过同一个 gateway；研究运行会锁定实际使用的 Skill 版本，保证回放一致。

## 11. Sandbox 安全边界

Runner 在独立服务中执行 JavaScript/Python：每次请求新容器、UID `65532`、只读 rootfs/source mount、drop capabilities、`no-new-privileges`、CPU/内存/PID/FD/超时/输出限制、默认 `--network none`，结束后删除容器。认证使用独立 token，metrics 使用独立 token；readiness 会检查容器引擎和镜像是否可用。当前不接受网络 Skill，因为共享网络无法落实每个 Skill 的域名级 egress grant。

## 12. 鉴权和隔离

账户使用数据库-backed opaque session，API Route Handler 先取得 viewer，再把 workspace 条件下推到查询。资源用 public ID 对外暴露，内部使用数据库 id。跨工作区资源按 not found 处理，避免泄露资源是否存在；注册、登录、邀请、执行等入口有 rate limit。

## 13. 面试前必背的取舍

1. 保留自研 Harness：已有 ledger、lease、retry、checkpoint、waiting-input 和审计，引入另一套 Agent runtime 会造成双状态。
2. 模型只提议动作：模型不直接写数据库、不改变权限、不跳过确认。
3. 默认公开网页搜索：平台 API/授权数据按需启用，失败要降级并记录，不虚构平台级数据。
4. 合成研究要标注边界：能做探索和假设，不能替代真实样本、行为日志或实验。
5. SSE 不等于权威状态：数据库事件和快照可回放，网络连接只是即时通知。

## 14. 验证方式

仓库提供 `pnpm lint`、`pnpm build` 和多组 smoke scripts，覆盖报告路由、Agent、实时访谈、证据图谱、Context hybrid retrieval、Skill executor、沙箱运行和任务恢复。隔离数据库 smoke 使用一次性 PostgreSQL，避免依赖远程生产数据。
